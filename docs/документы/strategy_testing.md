# Стратегия тестирования  
**Проект:** Клиент-серверная система с двухфакторной аутентификацией  
**Версия:** 1.0

## 1. Цели тестирования
- Проверить корректность двухфакторной аутентификации (логин/пароль + OTP).
- Убедиться, что пароли хранятся только в виде SHA-256 хэшей.
- Подтвердить механизм блокировки при брутфорсе OTP-кода.

## 2. Типы тестирования
| Тип | Приоритет | Объекты проверки |
|-----|-----------|------------------|
| Функциональное | Критический | Регистрация, авторизация, 2FA, сброс пароля, график |
| Безопасности | Критический | Хэширование паролей, блокировка после 4 неверных кодов |
| Интеграционное | Высокий | Клиент ↔ Сервер ↔ SQLite, Сервер ↔ SMTP |

## 3. Критические области
- Сравнение OTP-хэшей
- Флаги m_waitingFor*
- Хранение паролей (только хэши)
- Блокировка после 4 попыток

## 4. Окружения
| Среда | Конфигурация | SMTP | БД |
|-------|-------------|------|-----|
| dev | Локальная машина | Вывод кода в консоль | test.db |
| test | Docker-контейнер | Лог в консоль | test.db |
| prod | Выделенный хост | Реальный SMTP | production.db |

## 5. Инструменты
- Qt Test, PuTTY, Doxygen, Git

## 6. Критерии входа
- Сборка без ошибок, таблица users создана.

## 7. Критерии выхода
- Все тест-кейсы пройдены, нет критических багов, Doxygen без ошибок.

## 8. Регрессионное тестирование
При изменении FunctionsForServer или виджетов перезапускать тесты: TC_REG_01–TC_REG_05, TC_AUTH_01–TC_AUTH_05, TC_RESET_01–TC_RESET_04, TC_LOCK_01, TC_LOGOUT_01, TC_STATE_01.
