ТИМП — Подгруппа 5

Клиент-серверное приложение для графического отображения ветвящейся (кусочной) функции с системой двухфакторной аутентификации.

📘 Документация API (Doxygen) — справочная документация по всем классам и функциям проекта.

Описание проекта

Реализовано клиент-серверное приложение на языке C++17 с использованием фреймворка Qt 5. Проект выполнен в рамках дисциплины «Технологии Интернет и мультимедиа» (251/372), вариант 9 — кусочная функция.

Приложение состоит из двух независимых компонент:

  • Сервер — TCP-сервер на порту 33333, SQLite база данных, отправка email через Gmail SMTP
  • Клиент — GUI-приложение на Qt Widgets с полным жизненным циклом пользователя

Функциональность

  • Регистрация новых пользователей с email-верификацией (код подтверждения)
  • Авторизация по логину и паролю
  • Двухфакторная аутентификация (2FA) — ввод одноразового кода из email
  • Восстановление пароля через email
  • Построение и отрисовка графика кусочной функции:
f(x) = { |x·a| - 2,        при x < -2
       { b·x² + x + 1,    при -2 ≤ x < 2
       { |x - 2| + c,     при x ≥ 2

где a, b, c — параметры функции

  • Просмотр условия задания и блок-схемы алгоритма
  • Защита от перебора OTP-кодов (блокировка после 4 неверных попыток)

Быстрый старт

Собрать и запустить всё одной командой:

# Сборка и запуск сервера + клиента на одном ПК
./run.sh

# Либо отдельно — сервер на одном ПК, клиент на другом (LAN):
./run-server.sh             # на сервере, покажет IP
./run-client.sh 192.168.x.x # на клиенте, указав IP сервера

Для Docker-запуска сервера:

docker pull rainkord/timp-server:latest
docker run -d --name timp-server -p 33333:33333 rainkord/timp-server:latest

Диаграмма классов

В программе 10 основных классов. Клиентские виджеты взаимодействуют с сервером через ClientSingleton, сервер обрабатывает запросы через FunctionsForServer и хранит данные в DatabaseSingleton.

Стратегия тестирования

Цели тестирования

  • Проверить корректность двухфакторной аутентификации (логин/пароль + OTP)
  • Убедиться, что пароли хранятся только в виде SHA-256 хэшей
  • Подтвердить механизм блокировки при переборе OTP-кода
  • Проверить корректность вычисления кусочной функции и генерации графика

Типы тестирования

ТипПриоритетОбъекты проверки
ФункциональноеКритическийРегистрация, авторизация, 2FA, сброс пароля, график
БезопасностиКритическийХэширование паролей, блокировка после 4 неверных кодов
ИнтеграционноеВысокийКлиент ↔ Сервер ↔ SQLite, Сервер ↔ SMTP
МодульноеВысокийCalculator — вычисление f(x) для каждой ветки функции

Критические области

  • Сравнение OTP-хэшей (SHA-256)
  • Флаги m_waitingForCodeHash, m_waitingForSave
  • Хранение паролей — только хэши, никогда открытым текстом
  • Блокировка после 4 попыток ввода неверного кода
